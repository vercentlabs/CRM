## Phase 1 notes

- **Lockfiles:** one root `pnpm-lock.yaml`. Previously locked versions are pinned through `overrides` in `pnpm-workspace.yaml`; remove an override only as a deliberate upgrade.
- **API runtime:** `pnpm --filter @crm/api build`, then `node dist/server.js`. Dev uses `tsx watch`. The Docker images in `infrastructure/docker/` build from the repo root.

## Phase 2 notes

- **Behaviour changes (intentional):**
  - Access tokens now last 15 minutes and are backed by server sessions. Pre-Phase-2 24h tokens get 401, so users sign in again once.
  - The web app uses HttpOnly cookies and CSRF. Legacy `POST /auth/login` returns `{token, refreshToken, expiresIn, user}`.
  - Foreign-tenant ids return 404. The 403 body is generic, with no role details.
  - Managers keep their pre-Phase-2 rights. Admins now have organization-wide scope everywhere (e.g. they can edit any opportunity and complete any follow-up).
  - Creators with own scope (Sales) are the assignee of what they create (leads, customers, tasks, opportunities).
  - `/users` endpoints manage **memberships** of the active organization. An email that already exists becomes an `invited` membership and the identity is never modified. Identity fields can only be edited when the user belongs to no other organization.
  - Customer email uniqueness is per organization.
- **Bugs fixed while securing:**
  - The notes list threw for every Sales user (const reassignment).
  - `email.service` threw a ReferenceError and logged the reset URL, which contains the token.
  - Every lead message insert failed on `messages_type_check`.
  - Chat inserted into a missing `file_type` column (added in 0003).
  - Plivo verification called a non-existent SDK function and had no urlencoded parser.
  - The conversion report had SQL injection through `days`.
  - The CSV export had no line breaks.
  - The mobile drawer used the React Navigation 7 renamed `sceneContainerStyle`.
- **Web lint:** 0 errors (was 8). **Mobile typecheck:** 0 errors (was 10).
- **New operator commands:**
  - `pnpm org:bootstrap` (`BOOTSTRAP_ORG_NAME`, `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD`) creates an organization and its first admin.
  - `pnpm db:migrate` applies 0002 and 0003.

## Phase 3 notes

- **Architecture:** see `API.md`. `app.ts` only composes middleware, `/api/v1` (module registry), webhooks, legacy adapters and the error handler. There is one implementation per endpoint: legacy routes call the same services.
- **Removed:** every JavaScript backend file (`app.js`, `server.js`, `db.js`, `config/`, `controllers/`, `routes/`, `middleware/auth.middleware.js`, `services/`, `utils/`), the duplicate lead-message controller (both `/messages` and `/api/lead-messages` use `modules/messages`), `platform/organizations/{members,routes}.ts` and `platform/auth/routes.ts` (moved into modules), the `uuid` dependency, `allowJs`.
- **Behaviour changes (intentional, small):**
  - Legacy validation errors now come from the shared Zod schemas: same status and (reused) messages, plus `errors` details and `requestId`.
  - `/api/v1/organization/members` is paginated (`meta.pagination`, default 20).
  - Legacy responses carry `Deprecation: true`.
  - Chat attachments are uploaded under `organizations/<publicId>/chat/attachments` (max 10 MB, allowlisted MIME types), after authentication.
- **Inconsistencies kept on purpose (document, fix later with product input):**
  - Delete semantics differ: customers, tasks/calendar events and locations are deleted permanently; notes are soft-deleted (`is_deleted`); leads and opportunities cannot be deleted.
  - `PATCH /followups/:id/overdue` (legacy only) always answers 400 because the `followups.status` CHECK has no `Overdue` value; v1 has no such endpoint (overdue is computed).
  - The follow-up "list" is the lead call schedule (`leads.next_call_at`), not the `followups` table.
  - Chat presence stores the historical inverted flag; the API maps it so clients see the correct `is_online`.
  - Calendar events are a projection over tasks (no events table).
- **Phase 6 event candidates** (no bus yet; emit from these service functions): `lead.created` (leads.createLead), `lead.assigned` (leads.assignLead / createLead with assignee), `lead.status_changed` (leads.updateLead, incl. conversion → `customer.created`), `opportunity.stage_changed` (opportunities.updateOpportunity), `task.completed` (tasks.updateTask status → completed), `message.requested` (messages.sendMessage / sendBulk — today stored as `Sent` without a provider), `followup.scheduled` (leads.createFollowupForLead), `member.invited` (organizations.addMember).
- **Next:** Phase 4 moves the web app to `@crm/api-client` `client.v1.*` (cookie mode) and removes its legacy calls; Phase 5 does the same for mobile (bearer mode). Drop `users.role_id` and the legacy adapters only after both.

## Phase 4 notes

- **WEB_ROLEID_DEPENDENCY = NONE.** The web app never reads `roleId`; menus, actions and route gates use session permissions.
- **Web legacy API usage = NONE.** Every web call goes through `@crm/api-client` `client.v1.*`; `apps/web/test/architecture.test.ts` blocks endpoint strings, raw `fetch`/axios, `roleId`, token storage and HTML injection. (The backend legacy adapters were removed in Phase 5.)
- **Architecture:** see `WEB.md`. The web app is TypeScript (0 JavaScript sources), the pages are server components wrapping client screens, and Redux, axios and the three duplicate API helpers were removed.
- **`@crm/api-client`** gained `refreshSession` (single-flight refresh and retry on 401; never for anonymous calls) and `transport.raw`, used for the CSV export `reports.leadsCsv()`. Report DTOs were added to `@crm/types`, and request input types to `@crm/validation` (`crm/inputs.ts`).
- **Stale UI calls handled:** `/users/managers` → organization members (v1). `/gold/refresh` → `/market/gold-rate/refresh`. `/reports/export-{calls,customers,opportunities}-csv` had no API and their buttons were removed; the leads export uses `/reports/leads-export`. `GET /calls/:id` (never existed) → the call dialog tracks state locally. "Mark follow-up overdue" was removed (overdue is derived). `/ai/*` and `/integrations/google/*` are mobile-only (Phase 5).
- **Behaviour changes:** `/messages` now shows lead messages (it previously duplicated team chat at `/chat`). Old paths (`/lead-messages`, `/users`, `/admin`, `/audit`, `/reports/*`, `/followups/overdue`, `/locations/executives`) redirect. Organization settings edit real tenant keys (`site_name`, `timezone`, formats, page size); the old form saved camelCase keys the API rejected and implied SMTP settings could be edited.

## Phase 5 notes

- **Mobile architecture:** see `MOBILE.md`. The app was rebuilt on `@crm/api-client` (bearer), `@crm/types`, `@crm/validation` and `@crm/permissions` (now with `canIn`/`canAnyIn`/`canOrgIn`/`scopeIn`, shared with web). Access token in memory, refresh token in SecureStore only, single-flight refresh with rotation, org-scoped query keys, cache clearing and a navigation reset on organization switch. `apps/mobile/test/architecture.test.ts` blocks legacy endpoints, raw `fetch`/axios, numeric roles, token persistence, `/ai/*` and `/integrations/google/*`.
- **Removed (mobile):** the old screens, navigation, `AuthContext`, `services/*` (api, apiBase override, authStorage, aiAgent, leadEvents, themeStorage), placeholder/"coming soon" screens, the AI assistant (`/ai/*` never existed), the Google Calendar connection (`/integrations/google/*` never existed), map placeholder, CSV exports without an API, and unused dependencies (NativeWind, Tailwind, css-interop, linear-gradient, bottom tabs, masked view, react-native-svg). Mobile is now linted by the root ESLint config (with React Hooks rules).
- **Removed (API):** every `*.legacy.ts` adapter, `createLegacyRouter()`, `platform/http/legacy.ts` + `legacy-response.ts`, the pre-v1 `GET /health`, `req.user`/`ContextUser`, `requireAnyPermission`, `markFollowupOverdue`, the membership status toggle, `parseId`, the reports `userId` alias and `test/compatibility.test.ts`. Unknown paths (old ones included) answer the standard JSON 404; `apps/api/test/http.test.ts` asserts it for every old prefix. Plivo webhooks (`/api/plivo/webhook/*`) are unchanged. Security tests that used legacy URLs (auth, organizations, tenant isolation, HTTP guards, migrations) were rewritten against `/api/v1` with the same assertions.
- **Legacy role state:** `0004_remove_legacy_role_id.sql` drops `users.role_id` and `roles.legacy_role_id` (nothing reads them: 0003 already dropped the views/procedure that did). Built-in role rows keep ids 1/2/3. `roleId` was removed from `AuthUser`/session responses, `role_id` from `Member`, chat participants and `sender_role_id` from chat messages (types, API schemas, OpenAPI). `LEGACY_ROLE_IDS`/`builtInRoleKeyForLegacyId` and `legacyRoleId` on built-in roles were removed from `@crm/permissions`; member creation takes `roleKey` only.
- **Tests:** `apps/api/test/migration-0004.test.ts` upgrades a live 0003 database (two organizations, legacy `users.role_id` values, sessions, grants, CRM rows) and checks counts, memberships, sessions and logins; `migrations.test.ts` covers fresh installs and the 0001 → 0004 upgrade.
- **Behaviour changes:** clients still calling pre-v1 routes (for example an outdated mobile build) get 404 and must upgrade. Error responses outside `/api/v1` (webhooks) now use the standard envelope. Check-in on mobile is manual (no GPS module).
- **Deferred to Phase 7:** apply the organization `timezone` setting when formatting dates on web and mobile; device GPS check-in (`expo-location`, new native build); native E2E tests (Detox/Maestro); the pre-existing peer warning (`@react-navigation/elements` wants `@react-navigation/native` ≥ 7.4).

## Phase 6 notes

- **Architecture:** see `RUNTIME_PLATFORM.md`. Services publish events with `emit(tx, …)` inside the domain transaction; the worker relays `outbox_events` (SKIP LOCKED leases, dead-lettering after `OUTBOX_MAX_ATTEMPTS`) to four BullMQ queues. Without `REDIS_URL` (development and tests only) jobs run inline. Production requires Redis.
- **New packages:** `@crm/events` (event catalog + outbox writer), `@crm/entitlements` (feature and limit keys, resolution), `@crm/integrations` (storage/email/SMS adapters with timeouts and permanent/transient errors, webhook signing, secret encryption, SSRF guard). The API no longer imports ImageKit or nodemailer directly, and SDK clients are created lazily.
- **Behaviour changes (intentional):**
  - Lead messages start `Queued` and become `Sent` only after the provider accepts them (`Delivered` from Plivo reports; `Failed` with a reason). WhatsApp has no provider and fails with `CHANNEL_NOT_SUPPORTED`; SMS needs `SMS_PROVIDER=plivo` in the worker. Before Phase 6, every message was stored as `Sent` without any provider call.
  - Password-reset emails are sent by the worker; the token is created there and stored only hashed. The API response is unchanged (generic).
  - Invited existing users receive an invitation email.
  - Chat attachments should be sent with `file_id` (web and mobile do); `attachment_url` is still accepted from older clients, and historical attachments are untouched.
  - New error codes `FEATURE_NOT_ENABLED` (403) and `PLAN_LIMIT_REACHED` (409). Nothing is gated on the default plan.
- **Bugs found by the new tests:** ambiguous SQL parameter types (`$n` used both as a value and in `CASE`) in delivery-status updates would have silently rolled back failure handling; fixed with explicit casts.
- **Deferred to Phase 7:** webhook endpoint management API/UI (the delivery foundation is in place); push notifications; short-lived signed file URLs; outbox/queue metrics and alerting; the organization timezone for reminder copy and date display; device GPS check-in; native E2E.
